## 1. 新版一句话定位

> **Tap-to-Choice 是 DTC Dashboard 里的品牌问卷活动系统：品牌自己控制问什么，FC 系统负责把品牌配置好的选项题在正确的 magnet 场景中分发、记录和统计。**
> 

新版重点不是“系统替品牌选问题”，而是：

```
品牌创建问卷活动
↓
品牌配置问题和选项
↓
活动发布
↓
外部系统需要问卷时传入 magnet_id
↓
系统先根据 magnet 定位品牌，再根据用户 Klaviyo Segment 找到对应活动
↓
返回该活动下 1 个用户未答过的问题
↓
用户选择选项 / 选择 Other 并输入
↓
系统记录回答
↓
Dashboard 按活动、问题、选项、Other 汇总
```

---

## 2. 核心逻辑变化

| 模块 | 旧逻辑 | 新逻辑 |
| --- | --- | --- |
| 问题来源 | 系统根据规则从题库挑题 | 品牌在 DTC Dashboard 活动下创建问题 |
| 出题控制权 | FC Question Engine | 品牌 |
| 核心对象 | 问题规则 / 全局题库 | 问卷活动 |
| magnet 作用 | 作为规则上下文 | 用于定位品牌和展示来源；活动适用范围由 Klaviyo Segment 决定 |
| 问题类型 | 系统可配置多类问题 | P0 只支持选项题 |
| 文本输入 | 原则上不支持 | 只允许 Other 选项输入 |
| Dashboard | 按问题 / tag 统计 | 按活动 / 问题 / 选项 / Other 统计 |

<aside>
✅

**新版原则**：品牌决定问卷内容，FC 决定数据结构、校验规则、分发逻辑和统计口径。

</aside>

## 3. 产品边界

### 3.1 系统负责什么

P0 负责：

1. 品牌在 DTC Dashboard 创建问卷活动；
2. 品牌在活动下添加问题；
3. 品牌为每个问题添加选项；
4. 系统校验问题必须是选项题；
5. 系统允许“其它 / Other”作为唯一可输入选项；
6. 系统控制活动发布状态；
7. 系统根据 `magnet_id` 定位品牌，并根据用户所属 Klaviyo Segment 找到当前可用活动；
8. 系统返回活动下 1 个用户未答过的问题；
9. 系统记录展示、回答、跳过；
10. 系统生成活动 Dashboard。

### 3.2 系统不负责什么

P0 不负责：

- 不替品牌自动生成问卷；
- 不从全局题库自动挑选品牌未确认的问题；
- 不支持完全开放式回答；
- 不支持自由文本问答题；
- 不允许用户在非 Other 选项下输入文本；
- 不负责判断游戏流程是否展示问卷；
- 不负责领券发放；
- 不负责 Shopify / Klaviyo 回写；
- 不做复杂 AI 个性化问卷；
- 不在 P0 单独建设复杂标签体系、用户画像表或预聚合统计表。

## 5. DTC Dashboard 操作流程

### 5.1 品牌创建问卷活动

```
DTC Dashboard
↓
Survey Campaigns
↓
Create Campaign
```

创建活动时填写：

| 字段 | 说明 |
| --- | --- |
| 活动名称 | 品牌侧识别活动 |
| 活动目标 | preference / reward / product_discovery / feedback / vote |
| 活动说明 | 内部说明 |
| 适用 Klaviyo Segment | 全部用户或指定 Klaviyo Segment |
| 开始时间 | 可选 |
| 结束时间 | 可选 |
| 问题顺序 | fixed_order / random |
| 单用户最多回答题数 | 防止过度打扰 |
| 是否允许跳过 | 默认允许 |
| 状态 | draft / review / active / paused / archived |

### 5.2 品牌添加问题

每个活动下可以添加多道问题。

| 规则 | 要求 |
| --- | --- |
| 问题类型 | P0 只支持 `single_choice` |
| 问题文案 | 建议 20 字以内，最多 80 字 |
| 选项数量 | 2–4 个普通选项 |
| 是否可跳过 | 默认允许 |
| 是否必答 | P0 建议不强制 |
| 是否可输入 | 只有 Other 选项可以输入 |

### 5.3 品牌添加答案选项

每个问题下添加 2–4 个选项。

| 字段 | 说明 |
| --- | --- |
| 选项文案 | 用户看到的答案 |
| 选项值 | 系统内部 value，建议 snake_case |
| 展示顺序 | 1、2、3、4 |
| 是否 Other | 是否为“其它”选项 |
| 是否允许输入 | 只有 Other 可以打开 |
| Other 输入是否必填 | 可配置 |
| 最大输入长度 | 默认 100 字 |

## 6. 问卷格式规则

### 6.1 只允许选项题

P0 只开放：

```
single_choice
```

P1 可扩展：

```
multi_choice
```

不允许：

```
open_text
long_text
free_form
textarea
voice_answer
image_upload
```

### 6.2 Other 是唯一允许输入的形式

允许：

```
你更想要哪种奖励？
[免邮]
[新品试吃]
[小样加赠]
[其它：请填写]
```

不允许：

```
你有什么建议？
[自由输入框]
```

### 6.3 Other 校验规则

| 规则 | 要求 |
| --- | --- |
| Other 必须是一个选项 | 是 |
| Other 是否允许输入 | 可以 |
| 普通选项是否允许输入 | 不可以 |
| Other 文本长度 | 默认 100 字以内 |
| Other 文本是否进 Dashboard | 进入 Other Review 区 |
| Other 文本是否需要审核 | 建议需要 |

<aside>
⚠️

Other 的作用是补充品牌没有覆盖到的答案，不是开放式问卷。系统必须通过字段约束保证：只有 `is_other_option = true` 的选项，才能 `allow_text_input = true`。

</aside>

## 8. Survey Resolver 独立模块

虽然问题由品牌控制，但 **Survey Resolver 仍然必须独立实现**。

它不负责决定问题内容，而负责：

> **接收 `magnet_id` 和用户标识，先根据 `magnet_id` 定位品牌，再根据用户所属 Klaviyo Segment 找到品牌已发布且适用于该 Segment 的问卷活动，最后返回该活动下 1 个用户未答过的问题。**
> 

### 8.1 Survey Resolver 输入

```json
{
  "magnet_id": "mag_123",
  "fc_user_id": "user_123",
  "anonymous_id": null,
  "session_id": "sess_abc",
  "source_system": "game_engine"
}
```

### 8.2 Survey Resolver 调取的上下文

这里的“上下文”不再用于系统自动生成问题，而是用于定位活动和过滤问题。

| 上下文类型 | 字段 | 来源 | 用途 |
| --- | --- | --- | --- |
| Magnet Context | `magnet_id`、`magnet_code`、`status` | `magent` | 确认 magnet 存在且可用 |
| Customer Context | `customer_id`、`customer_category` | `magent` → `customers` | 找到品牌活动 |
| Campaign Scope | `survey_campaign_id`、`scope_type`、`priority` | `q_survey_campaigns` / `q_survey_campaign_segments` | 判断活动是否适用于该用户所属 Klaviyo Segment |
| Time Context | `start_at`、`end_at`、当前时间 | 活动配置 | 判断活动是否生效 |
| User Context | `fc_user_id`、`anonymous_id`、已答问题 | `q_survey_answer_events` | 排除用户已答问题 |
| Source Context | `source_system`、`session_id` | 外部系统 | 记录来源和分析 |

### 8.3 Survey Resolver 处理逻辑

```
1. 接收 magnet_id
2. 查询 magent，确认 magnet 存在且 active
3. 根据 magent 找到 customer_id
4. 根据 fc_user_id / anonymous_id 找到 Klaviyo profile
5. 查询该用户当前所属 Klaviyo Segment
6. 查询该 customer 下 active 的 q_survey_campaigns
7. 过滤时间未开始 / 已结束的活动
8. 过滤不适用于该用户 Klaviyo Segment 的活动
9. 如果多个活动命中，按 priority DESC、start_at DESC 选择
10. 查询该活动下 active 的 q_survey_questions
11. 排除当前用户已 answered 的问题
12. 根据 fixed_order / random 选择 1 个问题
13. 查询该问题下 active options
14. 写入 q_survey_impressions，并记录 magnet_id 作为来源
15. 返回 survey_campaign + question + options + impression_id
```

## 10. 核心数据表设计

### 10.1 q_survey_campaigns｜品牌问卷活动表

作用：品牌在 DTC Dashboard 中创建的问卷活动。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | UUID | 问卷活动 ID |
| `customer_id` | UUID | 品牌 / 客户 ID |
| `name` | TEXT | 活动名称 |
| `description` | TEXT | 活动说明 |
| `campaign_goal` | TEXT | 活动目标 |
| `scope_type` | TEXT | `all_users` / `selected_segments` |
| `status` | TEXT | draft / review / active / paused / archived |
| `start_at` | TIMESTAMP | 开始时间 |
| `end_at` | TIMESTAMP | 结束时间 |
| `priority` | INT | 多活动命中时优先级 |
| `question_order_policy` | TEXT | fixed_order / random |
| `max_questions_per_user` | INT | 单用户最多回答题数 |
| `allow_skip` | BOOLEAN | 是否允许跳过 |
| `created_by` | UUID | 创建人 |
| `created_at` | TIMESTAMP | 创建时间 |
| `updated_at` | TIMESTAMP | 更新时间 |

```sql
CREATE TABLE q_survey_campaigns (
  id UUID PRIMARY KEY,
  customer_id UUID NOT NULL REFERENCES customers(id),
  name TEXT NOT NULL,
  description TEXT,
  campaign_goal TEXT NOT NULL,
  scope_type TEXT NOT NULL DEFAULT 'selected_segments',
  status TEXT NOT NULL DEFAULT 'draft',
  start_at TIMESTAMP,
  end_at TIMESTAMP,
  priority INT NOT NULL DEFAULT 0,
  question_order_policy TEXT NOT NULL DEFAULT 'fixed_order',
  max_questions_per_user INT,
  allow_skip BOOLEAN NOT NULL DEFAULT true,
  created_by UUID,
  created_at TIMESTAMP NOT NULL DEFAULT now(),
  updated_at TIMESTAMP NOT NULL DEFAULT now(),

  CHECK (scope_type IN ('all_users', 'selected_segments')),
  CHECK (question_order_policy IN ('fixed_order', 'random'))
);
```

---

### 10.2 q_survey_campaign_segments｜活动适用 Klaviyo Segment 表

作用：当活动只适用于部分用户人群时，记录活动与 Klaviyo Segment 的适用关系。

> 问卷活动不直接绑定 magnet。`magnet_id` 只用于定位品牌和记录来源；真正决定这个用户是否命中活动的是用户当前所属的 Klaviyo Segment。
> 

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | UUID | 记录 ID |
| `survey_campaign_id` | UUID | 问卷活动 ID |
| `klaviyo_segment_id` | TEXT | Klaviyo Segment ID |
| `klaviyo_segment_name` | TEXT | Segment 名称快照，方便后台展示 |
| `priority` | INT | Segment 级优先级 |
| `status` | TEXT | active / inactive |
| `created_at` | TIMESTAMP | 创建时间 |

```sql
CREATE TABLE q_survey_campaign_segments (
  id UUID PRIMARY KEY,
  survey_campaign_id UUID NOT NULL REFERENCES q_survey_campaigns(id),
  klaviyo_segment_id TEXT NOT NULL,
  klaviyo_segment_name TEXT,
  priority INT NOT NULL DEFAULT 0,
  status TEXT NOT NULL DEFAULT 'active',
  created_at TIMESTAMP NOT NULL DEFAULT now(),
  UNIQUE(survey_campaign_id, klaviyo_segment_id)
);
```

### 10.3 q_survey_questions｜活动问题表

作用：存储某个问卷活动下的问题。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | UUID | 问题 ID |
| `survey_campaign_id` | UUID | 所属问卷活动 |
| `question_text` | TEXT | 问题文案 |
| `question_type` | TEXT | P0 只开放 single_choice |
| `display_order` | INT | 活动内展示顺序 |
| `is_required` | BOOLEAN | 是否必答 |
| `allow_skip` | BOOLEAN | 是否允许跳过 |
| `answer_policy` | TEXT | 默认 once_per_user |
| `status` | TEXT | active / inactive |
| `created_at` | TIMESTAMP | 创建时间 |
| `updated_at` | TIMESTAMP | 更新时间 |

```sql
CREATE TABLE q_survey_questions (
  id UUID PRIMARY KEY,
  survey_campaign_id UUID NOT NULL REFERENCES q_survey_campaigns(id),
  question_text TEXT NOT NULL,
  question_type TEXT NOT NULL DEFAULT 'single_choice',
  display_order INT NOT NULL DEFAULT 0,
  is_required BOOLEAN NOT NULL DEFAULT false,
  allow_skip BOOLEAN NOT NULL DEFAULT true,
  answer_policy TEXT NOT NULL DEFAULT 'once_per_user',
  status TEXT NOT NULL DEFAULT 'active',
  created_at TIMESTAMP NOT NULL DEFAULT now(),
  updated_at TIMESTAMP NOT NULL DEFAULT now(),

  CHECK (question_type IN ('single_choice', 'multi_choice'))
);
```

P0 说明：

> 数据库可以预留 `multi_choice`，但 DTC Dashboard 第一版只开放 `single_choice`。
>

### 10.4 q_survey_question_options｜问题选项表

作用：存储问题选项，并通过字段约束保证只有 Other 可以输入。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | UUID | 选项 ID |
| `survey_question_id` | UUID | 所属问题 |
| `label` | TEXT | 用户看到的选项 |
| `value` | TEXT | 系统内部值 |
| `display_order` | INT | 展示顺序 |
| `is_other_option` | BOOLEAN | 是否 Other |
| `allow_text_input` | BOOLEAN | 是否允许输入 |
| `other_text_required` | BOOLEAN | Other 文本是否必填 |
| `text_input_placeholder` | TEXT | 输入框提示 |
| `max_text_length` | INT | 最大输入长度 |
| `status` | TEXT | active / inactive |
| `created_at` | TIMESTAMP | 创建时间 |
| `updated_at` | TIMESTAMP | 更新时间 |

```sql
CREATE TABLE q_survey_question_options (
  id UUID PRIMARY KEY,
  survey_question_id UUID NOT NULL REFERENCES q_survey_questions(id),
  label TEXT NOT NULL,
  value TEXT NOT NULL,
  display_order INT NOT NULL DEFAULT 0,

  is_other_option BOOLEAN NOT NULL DEFAULT false,
  allow_text_input BOOLEAN NOT NULL DEFAULT false,
  other_text_required BOOLEAN NOT NULL DEFAULT false,
  text_input_placeholder TEXT,
  max_text_length INT NOT NULL DEFAULT 100,

  status TEXT NOT NULL DEFAULT 'active',
  created_at TIMESTAMP NOT NULL DEFAULT now(),
  updated_at TIMESTAMP NOT NULL DEFAULT now(),

  CHECK (
    allow_text_input = false
    OR is_other_option = true
  )
);
```

关键规则：

```
allow_text_input = true
↓
必须 is_other_option = true
```

### 10.6 q_survey_answer_events｜问卷回答事件表

作用：记录用户选择 / 跳过。  

`other_text` 只在选择 Other 选项时允许写入。

| 字段 | 类型 | 说明 |
| --- | --- | --- |

| `source_system` | TEXT | 外部来源 |

```sql
CREATE TABLE q_survey_answer_events (
  id UUID PRIMARY KEY,
  impression_id UUID REFERENCES q_survey_impressions(id),
  survey_campaign_id UUID NOT NULL REFERENCES q_survey_campaigns(id),
  survey_question_id UUID NOT NULL REFERENCES q_survey_questions(id),
  survey_option_id UUID REFERENCES q_survey_question_options(id),

  customer_id UUID NOT NULL REFERENCES customers(id),
  magnet_id UUID NOT NULL REFERENCES magent(id),
  fc_user_id UUID,
  anonymous_id TEXT,
  session_id TEXT,

  action TEXT NOT NULL,
  selected_value TEXT,
  other_text TEXT,
  response_time_ms INT,
  source_system TEXT,
  created_at TIMESTAMP NOT NULL DEFAULT now(),

  CHECK (action IN ('answered', 'skipped'))
);
```

应用层必须校验：

```
如果 other_text 不为空：
1. survey_option_id 必须存在
2. option.is_other_option 必须为 true
3. option.allow_text_input 必须为 true
4. 长度必须 <= option.max_text_length
```

## 11. 发布校验规则

品牌点击 Publish 前，系统必须校验：

| 校验项 | 规则 |
| --- | --- |
| 活动名称 | 必填 |
| 活动目标 | 必填 |

| 时间 | end_at 必须晚于 start_at |

如果校验不通过，活动不能发布，只能保持 draft / review。

## 13. Resolve SQL 示例

```sql
WITH matched_campaigns AS (
  SELECT
    sc.*,
    COALESCE(MAX(scs.priority), 0) AS segment_priority
  FROM q_survey_campaigns sc
  LEFT JOIN q_survey_campaign_segments scs
    ON scs.survey_campaign_id = sc.id
   AND scs.status = 'active'
   AND scs.klaviyo_segment_id IN (:klaviyo_segment_ids)
  WHERE sc.customer_id = :customer_id
    AND sc.status = 'active'
    AND (sc.start_at IS NULL OR sc.start_at <= now())
    AND (sc.end_at IS NULL OR sc.end_at >= now())
    AND (
      sc.scope_type = 'all_users'
      OR scs.id IS NOT NULL
    )
  GROUP BY sc.id
  ORDER BY
    segment_priority DESC,
    sc.priority DESC,
    sc.start_at DESC NULLS LAST
  LIMIT 1
)

SELECT q.*
FROM q_survey_questions q
JOIN matched_campaigns mc
  ON mc.id = q.survey_campaign_id
WHERE q.status = 'active'
  AND NOT EXISTS (
    SELECT 1
    FROM q_survey_answer_events ae
    WHERE ae.survey_question_id = q.id
      AND ae.action = 'answered'
      AND (
        (:fc_user_id IS NOT NULL AND ae.fc_user_id = :fc_user_id)
        OR (:anonymous_id IS NOT NULL AND ae.anonymous_id = :anonymous_id)
      )
  )
ORDER BY
  CASE
    WHEN (SELECT question_order_policy FROM matched_campaigns) = 'fixed_order'
    THEN q.display_order
  END ASC,
  random()
LIMIT 1;
```

## 18. 最终实现判断

<aside>
✅

**最终判断**：新版 Tap-to-Choice P0 应该保持数据库极简。品牌控制问卷问题和答案，FC 系统只需要 6 张新表完成活动创建、问题选项管理、Klaviyo Segment 活动匹配、magnet 来源记录、回答记录和 Dashboard 查询。

</aside>

最终闭环：

```
Brand creates Survey Campaign
↓
Brand adds Questions
↓
Brand adds Options / Other
↓
Campaign published
↓
magnet_id identifies customer
↓
Klaviyo Segment resolves active campaign
↓
return one unanswered question
↓
user selects option / Other
↓
survey impression + answer event
↓
survey dashboard
```

P0 最重要的是保证：

1. 品牌可以自主创建问卷活动；
2. 问题必须是选项题；
3. 只有 Other 允许输入；
4. `magnet_id` 能定位品牌，Klaviyo Segment 能定位正确活动；
5. 用户答过的问题不重复返回；
6. 回答事件和 Other 文本完整记录；
7. Dashboard 能按活动、问题、选项、Other 查询；
8. P0 只新增 6 张核心表，避免过度设计。
